FWPS · PDF 内嵌阅读助手 UI / 回答排版 / 字体方案
日期：2026-10-30

交付范围
这是基于截图与现有 Rust / egui 源码的设计提案，不是已集成的程序修改。
双击 index.html 可离线预览；无需构建、依赖或联网。所有回答与 PDF 内容均为设计示例。
顶部可切换完整阅读器、420px 侧栏、340px 侧栏及回答状态；设置内可切换字体和字号。
design-tokens.json 是供开发转换的设计参数，不是 egui 可直接加载的配置文件。

一、现状与调整依据

1. 配置区挤占首屏
截图的重新连接、API 配置、导入、清空、模型选择和提示占据明显空间。
将 API 配置、导入配置、重连移到右上角设置；标题行只保留“阅读助手”、连接状态和收起。
模型移到输入框下沿。错误发生时，就近显示错误与重试入口，不依赖设置页发现错误。
“pi agent”是实现细节，放入关于/设置，不与产品标题并列。

2. 输入区与消息区倒置
现状先输入再看到回答。改为：标题 → 模式 → 文档上下文 → 可滚动消息 → 固定输入区。
只让消息列表滚动；输入区保持可见。顶部、底部采用细边线，避免每段回答加粗分隔线。
用户向上阅读历史时，流式回答不得强制拉回底部；展示“回到最新”入口。

3. 模式和“长期开启”重复
保留“问文档 / 翻译与解释”两个页签。
翻译页内依次为：选区摘要、目标语言、结果、输出方式、选中后自动翻译。
输出方式用单选：仅翻译 / 翻译并解释；自动翻译只保留一个开关，对应现有互斥语义。
没有选区时提供说明“在 PDF 中选中文字后翻译”，保留语言与开关偏好。
现有右键翻译入口继续保留，触发后定位翻译页签。

4. Markdown 未渲染
现有 ai_reader.rs 逐条用 egui::Label::new(text) 展示，截图直接露出 ** 和反引号。
优先支持段落、加粗、行内代码、列表、标题、代码块、引用、表格。
代码和标识符使用等宽字体。正文可选择复制，复制整条回答时提供纯文本；可进一步提供复制 Markdown。
不能只做字符串替换来移除 **：会损失结构，且错误处理嵌套、转义与代码块。
PDF 文本、模型回答及代码块里的指令都是内容，不作为 UI 命令执行。

二、信息布局与尺寸（逻辑 px / egui points，按 100% 缩放定义）

推荐侧栏宽：420；舒适范围：380–480；兼容宽：340。
现有最小宽 220、默认宽 340、最大宽通常 600；建议默认改为 420，并根据主窗口余量限制。
220–319 宽不作为常规阅读宽度：如果必须支持，页签与快捷动作换行、隐藏次要元信息；
在主窗口过窄时允许助手成为覆盖层。桌面横向布局需给 PDF 保留足够宽度。
HTML 原型在窄屏只展示助手；这只是展示方式，不要求原生程序复制浏览器断点。

标题区：64 高；页签区：39 高；文档上下文条：约 36 高。
面板内边距：20–24；消息间距：24；段间距：12–16；常规控件高：30–34。
输入框：至少 2 行，随内容增长至约 140，再内部滚动；底部操作区不覆盖回答。
输入区上方提供“总结本页 / 文档概览 / 新对话”。新对话只清会话，不重置 API 和阅读偏好。
侧栏与 PDF 用 1px 中性分隔线，支持现有拖拽宽度，不添加大投影。
按钮圆角：6–8；输入框：10–11；用户消息：12；助手正文不加大气泡背景。
全局仅保留一个明显主按钮（发送或停止）；快捷任务用轻量文字按钮。

三、回答 UI 规范

用户消息：右侧浅灰底，最大宽度约 92%，13–14px，行高 1.7。
助手消息：左对齐，无整块气泡；小图标 +“阅读助手”+ 来源范围。
第一段直接给结论，随后按问题需要提供解释、列表、表格和限制条件。
避免每段都加标题；简短问答只需一两段。

建议内容结构：
  ICP 是 PHY 的寄存器访问接口
  它通过独立地址与控制信号完成寄存器读写。[58]
  三个关键信号：信号 / 作用（两列表格）
  不确定性：具体时序需进一步查阅对应章节。

引用：优先放在支持结论的句尾，采用“58 ↗”小标签；底部汇总“参考来源 第 58 页”。
不是所有出现的数字都能解析成页码；保留现有 cited_pages 的校验与文档页数边界。
页码需绑定生成时的文档身份和来源，防止切换文档后跳到另一份 PDF 的相同页。
内部通常从 0 计数，界面从 1 计数；沿用现有返回 Option<u32> 的跳转路径。
若只有页码证据，点击仅跳页；只有定位到真实选区/文本框时才高亮对应段落。
原型的高亮与正文均为示例，不代表已有文本定位功能。

来源范围：当前页 / 选区 / 实际读取页，必须与请求实际上下文一致。
“文档概览”要列出实际阅读页码；仅抽样时标记“抽样概览”，不能声称读完全文。
证据不足时采用普通信息段落说明，只有连接/请求失败才使用错误状态。
回答底部提供复制、重新生成；先做高频操作，避免常驻一排低频图标。
长代码块和多列表格独立横向滚动，不撑宽整个侧栏；正文换行保留标识符可读性。

四、字体方案（推荐先落地 A，B/C 作为回答阅读偏好）

A 清晰 / 默认
  导航、按钮、设置：Segoe UI Variable Text / Segoe UI；中文回退 Microsoft YaHei UI / Microsoft YaHei。
  回答正文：同系统无衬线栈，15px / 1.85（约 28px 行高）。
  助手标题：15px、600；答案小标题：15–16px、600，行高 1.55。
  按钮/问题：13px；上下文：12px；次要元信息：11–12px。
  适合中英文混合技术文档，是默认方案。

B 书卷 / 长文阅读
  只改变回答正文：Noto Serif CJK SC / Source Han Serif SC / SimSun / serif，16px、行高 1.9。
  导航与输入仍使用 A；代码仍用等宽；宋体不用于小尺寸按钮。
  Windows 未安装思源宋体时回退宋体，效果会随系统不同；原型不下载或打包字体。

C 紧凑 / 工程阅读
  系统无衬线 14px、行高 1.75；标题 15px；表格 12–13px；代码 12px。
  用于信号、寄存器密集内容，不把普通中文段落全部改成等宽。
  原型 C 展示 14px 系统正文；行高统一为 1.85 以方便窄侧栏比较。

代码栈：Consolas / Cascadia Code / monospace；行内代码 12–13px，浅灰底、细边线、4px 圆角。
代码内中文仍需中文字体回退。避免靠新增字体名称自动获得 egui 回退能力。

字号偏好：14 / 15 / 16 / 18，建议默认 15。
原型字号用 CSS px；原生落地用 egui 逻辑 points，跟随现有 DPI 缩放，不把屏幕像素直接当 points。
正文行距及段间距独立设置；不要通过放大整个程序使助手更易读。
现有 app.rs 已将微软雅黑/黑体加入 Proportional 字体族；要明确注册拉丁、中文和代码字体的顺序。
egui 的 FontId 主要包含字号与字体族，“600 字重”需注册独立字重字体族或使用合适字体数据，
不能只按 CSS 字重照搬。微软雅黑通常无可调 weight 参数；缺少真实字重时保持普通正文与 strong 层级即可。
原生宽度建议用 points；字体需从目标系统读取并处理缺失，不把系统字体文件复制进发布包。

五、配色与视觉约束

浅色：背景 #EEE FEE（无空格为 #EEEFEE）；面板 #FFFFFF；次级底 #F5F6F6。
正文 #252B32；次要文字 #626A76；分隔线 #E4E7EB。
强调 #5550B8；强调浅底 #EFEDFB；连接成功 #36745C；错误 #A53939。
深色：背景 #191C21；面板 #22262D；次级底 #2C313A。
正文 #E2E5EB；次要文字 #A5ADBB；边线 #383E49；强调 #B2A8F5；强调浅底 #36314E。
深色实心主按钮单独采用 #7B6CD1 + 白字。
不要用强调色填充整条回答。页签、引用、焦点环使用相同强调语义。
保留系统 PDF 阅读主题；深色助手不强制把文档反色。
键盘聚焦至少 2px 可见描边；连接状态同时有文字；错误不只依赖红色表达。
重要说明不低于 12px，原型底部“离线演示”等 10px 文本只用于演示元信息，正式版建议不小于 11–12pt。
原型尚未执行完整无障碍审计；交付前需在目标字体、DPI、主题上确认对比度和焦点顺序。

六、完整状态与交互

初次使用：提示从当前页开始，提供“总结当前页”，无历史空白框。
没有 PDF：提示“打开一份 PDF 后开始问答”，保留设置与测试连接；禁用文档任务。
没有选区：翻译页提示选中文字，不显示一排灰色不可用大按钮。
正在生成：状态标记“正在阅读/正在生成”，输入框发送变为停止，草稿可编辑。
流式内容：用稳定段落块呈现；未闭合代码围栏暂按代码或普通文本处理，避免抖动。
完成：取消生成态，显示复制/重新生成和实际来源，继续保留输入焦点。
用户停止：保留已生成文字，标记“已停止”，不得替换为成功完成。
网络/API 错误：保留草稿与已经生成的回答；错误就近展示，提供重试与检查配置。
切换模型/重连：若会中止当前回答，要在该操作旁说明；避免模型选择导致无提示中断。
清空会话：使用“新对话”，不清除服务配置、语言及自动翻译偏好。
自动翻译：保留现有互斥状态和请求中止机制，避免旧流覆盖新选区。
发送：保留 Ctrl+Enter，Enter 换行；中文输入法组合期间不触发发送。

七、与当前项目的对应关系

已阅读文件：
  src/ai_reader.rs：侧栏 show()（约 385–590 行）、模型和 API 设置、翻译开关、纯文本消息。
  src/app.rs：字体初始化（约 173–196 行）、全局字号缩放控制（约 1332 行起）。
  Cargo.toml：eframe 固定 =0.33.3，当前未列 Markdown 渲染依赖。
本次仅新增方案文件夹，不修改上述文件，不构建或替换现有可执行程序。

建议原生组件拆分：
  show_header / show_mode_tabs / show_document_context
  show_chat / render_message / render_markdown_blocks / render_citations
  show_composer / show_translation_options / show_settings
  AgentAppearance（正文大小、字体偏好、主题 token）

布局顺序：先分配底部 composer 和顶部 header，再让中间 ScrollArea 使用剩余高度。
用侧栏局部 style/scope 调整按钮和间距，不改变主 PDF 全局 text_styles。
文档内容、问题字符串、引用目标与显示布局分离；render_message 不负责发送请求。
沿用 controls 标识符：ai-close、ai-config、ai-config-import、ai-model、ai-summary、
ai-translate、ai-auto-translate、ai-explain、ai-auto-explain、ai-question-input、
ai-question-send、ai-citation 等；旧自动化命中点迁移需有对应关系。
页签隐藏内容时先清理过期控件 rect，避免 smoke 测试命中旧位置。

Markdown 实现方式：
  先确认适配 egui 0.33.3 的解析器/渲染器版本，再引入依赖；此设计未验证第三方库兼容性。
  也可做小型受限块渲染层：解析块结构，再将段落/行内样式转换为 LayoutJob。
  表格需自定义换行和横向滚动；代码块保留空白，不把 Rust 等代码里的星号当强调。
  流式缓存已完成块，仅重算最后一个未完成块，避免每个 token 重排整段历史。
  将引用解析结果映射为可点击控件；不要启用任意 HTML 或自动执行外部协议。

八、实施优先级与验收

P0：布局重排、配置收纳、固定输入、Markdown 基础块、代码字体、引用。
P1：翻译页签与互斥模式、回答字号、深色 token、错误和停止状态。
P2：来源段落定位、历史折叠、表格与代码块专用横向滚动、长回答渲染优化。

原生完成后验证：
  340 / 420 / 600pt 侧栏，100% / 125% / 150% / 200% DPI；中英混排和长信号名。
  无 PDF、无选区、长回答、表格、代码块、未闭合 Markdown、流式更新与中断。
  连续切换文档和选区，确认引用不会跳错文档、旧回答不会覆盖新回答。
  所有模式可通过键盘访问，Ctrl+Enter 可用，中文输入法与选择复制正常。
  使用项目既有 cargo fmt --check、clippy、cargo test，以及 --smoke-ui 截图检查。
  本次没有修改 Rust，未运行这些原生工程检查；原型只验证浏览器内的布局与示例交互。

原型限制
  固定回答用于排版展示，任意问题均不会触发真实检索或模型调用。
  “文档概览”“解释读取过程”等动作展示同一固定示例；翻译为预置样例。
  设置和偏好不持久保存；API 项只展示说明，不接收密钥；复制依赖浏览器剪贴板权限。
  收起/恢复、页签、主题、字体、字号、尺寸、状态、停止、示例引用均可操作。
  左侧目录和顶部页码是静态上下文，不是完整 PDF 阅读器。
